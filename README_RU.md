# KotNode Project 0.2.1 — исправление вставки

> Полная хронология развития конструктора параметрических семейств, 3D-углов, ассоциативного оформления, ВРС и визуальной верификации в AutoCAD 2026: [`docs/DEVELOPMENT_HISTORY_RU.md`](docs/DEVELOPMENT_HISTORY_RU.md).

Исправлен NullReferenceException при обработке обычных ячеек таблиц. Подробности — `HOTFIX-0.2.1.md`. Добавлены команды **NPVERSION** и **NPLOG**, подробный журнал исключений. Перед установкой полностью перезапустите AutoCAD.

Полная версия **AutoCAD 2021 / Windows x64 / .NET Framework 4.8**. Готовые DLL находятся в `plugin`. LISP для работы не нужен. Версия 0.2 сохраняет диспетчер проекта из 0.1 и возвращает детальное оформление узла «труба–труба».

## Установка и первый прогон

1. Распакуйте архив в отдельную постоянную папку. Если скачанные DLL заблокированы Windows, снимите блокировку в их свойствах. При запросе доверия AutoCAD добавьте папку `plugin` в доверенные расположения.
2. **Перезапустите AutoCAD**, если ранее загружали DLL версии 0.1. Заменить уже загруженную .NET-сборку в том же процессе нельзя.
3. Выполните **NETLOAD** → `plugin/KotNode.AutoCAD.dll`. Файл `KotNode.Core.dll` должен лежать рядом.
4. Выполните **NPROJECT** → откройте ваш проект 0.1 либо `examples/demo.knproject.json`.
5. Для вставки используйте мировую ПСК, миллиметры: `UCS → World`, `INSUNITS=4`.
6. Вкладка «Марки узлов» → выбрать У-01 → «Вставить виды» → масштаб оформления (например, 20) → точка.

При вставке теперь создаются **продольный вид, сечение, размеры, выноски, спецификация и локальная ведомость расхода стали**. Проектные количества берутся из включенных применений. Дополнительная вставка изображения не добавляет узлов в расход.

## Что вернулось в чертеж

- Две проекции с видимыми и скрытыми контурами накладок; скрытые стенки труб.
- Оси и скрытые линии с геометрическим штрихованием, как в 0.7: их шаг не зависит от LTSCALE и режима просмотра блока.
- S-образные разрывы труб, заголовки и обозначения сечения.
- Продольные ряды крестиков швов на фактических кромках проекций, с ограничением размера символа по ширине зазора.
- Торцевые швы накладок как отдельная опция, независимая от стыкового шва.
- По два заполненных треугольника швов на каждой накладке в сечении.
- Размер длины накладки, размер зазора (если он есть), размер между накладками в свету, дуговой размер каждой накладки и два угловых размера половин сектора.
- Самостоятельные MLeader: швы на продольном виде и сечении, труба, позиция накладки, стыковой шов при его наличии. Продольная выноска швов имеет две стрелки.
- Нативные таблицы с заголовками, обозначением трубы-заготовки, сталью, массами на деталь/узел/все применения, итогами в кг и т.

Шрифт — ISOCPEUR, геометрия 1:1 в миллиметрах. Размеры — **внешние штатные Dimension**, а не примитивы внутри блоков. Приватный размерный стиль содержит косые засечки и параметры оформления, перенесенные из 0.7. Обозначения и ссылки на ГОСТ в выносках перенесены как часть исходного шаблона, без проверки применимости к конкретному проекту.

## Ручное оформление и обновление

Вид и его размеры объединены в именованную группу AutoCAD. При `PICKSTYLE=1` (либо 3) обычный MOVE переносит их вместе. Выноски и таблицы перемещаются независимо. Программа не меняет PICKSTYLE глобально.

После перемещения вида или изменения марки выполните **NPUPDATE**. Обновление:

- сохраняет сами вхождения блоков и размерные объекты по постоянным ролям;
- пересчитывает привязки и сохраняет ручные смещения размерных линий и текста;
- учитывает, были ли размеры уже перенесены вместе с видом, чтобы не сдвигать их дважды;
- меняет первые точки линий выносок, сохраняя полки и остальные вершины;
- сохраняет пользовательские дополнительные ветви MLeader;
- добавляет/удаляет только элементы, которые появились/исчезли по параметрам, например размер зазора и выноску стыкового шва;
- обновляет связанные спецификации и ведомости **на месте**, сохраняя положение и ширину существующих столбцов. При изменении структуры таблицы число строк/столбцов приводится к новой форме. Содержимое расчетных ячеек и объединения служебных строк генерируются заново.

Поддерживаются переносы плоских видов без поворота и масштабирования вхождений. Геометрию внутри блока следует менять через параметры марки: ручные правки линий при обновлении заменяются.

## Обновление DWG версии 0.1

Откройте тот же файл проекта и выполните **NPUPDATE** в DWG со связанными видами 0.1. Новые размеры/выноски будут добавлены, упрощенные объекты заменены; положение видов сохранится. Старый размер длины мигрирует в новый; лишний диаметр из 0.1 удаляется.

**В существующий комплект 0.1 локальная ведомость автоматически не добавляется**, если ее там не было. Для полного нового комплекта используйте «Вставить виды». Таблицы, которые уже были связаны с проектом, обновятся.

NPSTATUS учитывает как редакцию марки, так и версию оформления: исходные виды 0.1 считаются требующими обновления даже без изменения параметров.

Миграции из LISP-узлов пока нет. Чертежи 0.7 остаются отдельными. Для проверки можно разместить узлы двух систем рядом при одинаковых параметрах.

## Параметры

Сохранились параметры 0.1; добавлены позиция накладки, номер сечения, опция торцевых швов. Поддерживается от 1 до 12 накладок. При одной накладке задается угол сектора; при нескольких — расстояние в свету, угол рассчитывается. Недопустимый набор размеров не сохраняется.

При стыковом шве расчетный зазор равен нулю, поле зазора отключено. Введенное значение хранится для возврата к соединению без стыкового шва. Материал и толщина накладки независимы от основной трубы.

Проекты 0.1 читаются без ручного редактирования JSON; отсутствующие параметры оформления получают совместимые значения по умолчанию. Изменение марки увеличивает ее редакцию и пересчитывает все применения этой марки.

## Проект и количество стали

Основной файл — `*.knproject.json` в общей папке. Марки, детали и применения имеют постоянные GUID. В DWG хранятся XRecord со связью с проектом и снимком параметров.

Количество определяется **только включенными применениями**, а не числом изображений. Новые применения по умолчанию черновые. Пример: 24 узла на ярусе 1 + 6 на ярусе 2 = 30 узлов / 120 накладок. Еще 10 узлов в строке «Вариант» исключены.

В спецификации строка узла показывает общее количество применений; строка детали — состав одного узла. Отдельная строка итога и локальная ВРС показывают суммарный расход по применениям. При отсутствии включенных применений общий расход равен нулю, масса одной детали и состав на один узел остаются видимыми.

Учитываются только накладки. Масса вычисляется по объему кольцевого сектора и плотности 7850 кг/м³, без металла швов, отходов и припусков. Исправленный коэффициент 0.5 из версии 0.1 сохранен; ошибочный коэффициент 0.7 из LISP в расчеты не возвращается.

CSV со вкладки «Расход стали» учитывает выбранный участок, содержит источники количества и сводку по стали/толщине. Команда NPTABLE и кнопка «Таблица всего проекта» всегда выводят весь проект.

## Совместное редактирование

Сохранение реестра использует исключительную файловую блокировку, проверку исходной версии, запись временного файла и атомарную замену. `.bak` — предыдущая версия, `.lock` — файл для блокировки (его наличие само по себе не означает занятого проекта).

Если другой инженер уже сохранил проект, ваша запись остановится. Нажмите «Обновить» и повторите изменение. DWG сохраняется отдельно; UNDO чертежа не отменяет запись реестра. Автослияния, офлайн-очереди и автоматического обхода закрытых DWG нет.

Обычная COPY дает несвязанную графическую копию. Для дополнительного связанного комплекта используйте диспетчер. Буфер обмена между DWG и WBLOCK пока не поддерживаются как способы переноса связей.

## Команды

| Команда | Назначение |
|---|---|
| NPROJECT | Диспетчер проекта |
| NPPLACE | Полный комплект выбранной марки; удобнее кнопкой из диспетчера |
| NPUPDATE | Обновить виды, оформление и связанные таблицы текущего DWG |
| NPSTATUS | Проверить редакции и версии оформления текущего DWG |
| NPSPEC | Дополнительная спецификация марки, оформление 1:20 |
| NPTABLE | Сводный расход всего проекта, оформление 1:20 |
| NPINFO | Прочитать связь и параметры выбранного объекта; доступно без открытого реестра |

## Проверки и исходники

- `src/Core/Drafting.cs`: независимый от AutoCAD план геометрии, размеров и выносок.
- `src/AutoCAD/Drawing.cs`: нативный рендерер и обновление объектов.
- `tests/fixtures/lisp07.json`: результаты исполнения исходных функций LISP 0.7.
- `tests/oracle`: неизмененный эталонный LISP и интерпретатор для повторного получения результатов.
- `PARITY.md`: матрица восстановления функций и границы проверки.
- `preview/node-plan.png`: расчетный предпросмотр, **не скриншот AutoCAD**. Он не подтверждает нативное отображение размеров.

Сборка — `powershell -ExecutionPolicy Bypass -File .\build.ps1`, нужен .NET SDK 8. Для запуска готовых DLL SDK не нужен.

**AutoCAD в среде разработки отсутствует.** Выполнена компиляция по API AutoCAD 2021 и автоматическое сравнение расчетных координат. Загрузка, реальное отображение Dimension/MLeader, работа ручек, групп, таблиц, UNDO и повторное открытие DWG требуют проверки на вашей Windows-машине по `WINDOWS_CHECK.md`.
