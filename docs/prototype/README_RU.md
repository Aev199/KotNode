# KotNode — прототип проекций из параметров

AutoCAD 2021, Windows x64, .NET Framework 4.8. Сборка для проверки подхода,
не замена всех видов конструктора. Все изображения размещаются в МОДЕЛИ.
Расчёт использует параметры из базы марки, без HLR AutoCAD, FLATSHOT и Open CASCADE.

## Быстрая проверка

1. Распаковать архив целиком в новую папку. Перезапустить AutoCAD, если загружена старая DLL.
2. Создать новый пустой DWG. Перейти на вкладку «Модель». INSUNITS=4 (мм), TILEMODE=1.
3. NETLOAD → KotNode.AutoCAD.dll. KotNode.Core.dll должен лежать рядом.
4. Выполнить NAPDEMO, затем _ZOOM → _Extents (Показать всё).
5. Справа от исходной 3D-сборки появятся два вида и два разреза.

Ожидаемый результат показан в preview.png. Это визуализация того же расчёта Core,
а не снимок AutoCAD: отображение нативных объектов необходимо проверить в AutoCAD.

Сборка: труба 100×10, длина 200 мм; пластина перед торцом, закрывающая половину
проекции трубы; маленькая пластина внутри полости за поперечной секущей плоскостью.

Проверить:
- На виде вдоль трубы передняя пластина закрывает правые полуокружности.
  Закрытые участки штриховые; маленькая пластина частично видна в полости.
- На виде сбоку показаны внутренние скрытые образующие трубы.
- На поперечном разрезе передняя пластина исчезает, стенка трубы штрихуется кольцом,
  отверстие не заштриховано. В отверстии видна маленькая пластина за плоскостью.
- На продольном разрезе видны две стенки трубы и пересечённые пластины.
  Незаштрихованные линии за плоскостью сохраняются: это разрез, а не только сечение.

## Свои представления и обновление

NAPVIEW — выбрать направление, название, скрытые линии, масштаб оформления и точку.
NAPSECTION — дополнительно выбрать точку секущей плоскости и включение штриховки.
Наблюдатель находится со стороны +Z выбранной системы вида; разрез сохраняет Z<=0.
Изображение строится в мировой XY в натуральных миллиметрах (1:1).
Масштаб оформления влияет на шаг штриховки и штриховых линий, не на размеры геометрии.

Использовать существующие команды редактирования параметров деталей конструктора.
После изменения диаметра трубы, толщины/длины пластины или перемещения детали
выполнить NAUPDATEVIEWS либо NAUPDATEVIEW для одного изображения.
Сдвинутый через MOVE блок вида должен сохранить своё положение.
NAEDITVIEW позволяет изменить параметры представления.

Механизм обновляет геометрию блока. Прямые ручные изменения внутри этого блока
перезаписываются. Сохранение привязок внешних размеров и выносок не реализовано
и в рамках этого прототипа не заявляется. Редактирование тел через BEDIT не меняет
параметры базы и не является поддерживаемым способом изменения исходной формы.

## Границы прототипа

- Только прямые круглые трубы и прямоугольные пластины без отверстий.
- Ось трубы должна быть параллельна одной из осей вида; её поворот вокруг собственной
  оси произвольный. Рёбра пластин должны быть параллельны осям вида.
- Детали могут перекрывать друг друга в проекции, но не проникать объёмами друг в друга.
  Касание допустимо. Для разнонаправленных труб пересекающиеся габариты отклоняются
  консервативно, даже если сами трубы фактически не пересекаются.
- Не поддержаны наклонные виды относительно осей деталей, двутавры, арматура,
  криволинейные и контурные пластины. Любая неподдерживаемая деталь останавливает
  создание всего изображения с понятным сообщением.
- Касательная плоскость и плоскость, совпадающая с торцом, не создают штриховку среза.
- NAVIEW/NASECTION сохраняют прежний экспериментальный FLATSHOT-маршрут.
  Для нового механизма нужны именно NAPVIEW/NAPSECTION.

В DWG сохраняются стандартные BlockReference, Line, Circle, Arc, Hatch и подписи DBText.
Просмотр и обычное ручное редактирование не требуют плагина; пересчёт требует плагина.

## Как проверен расчёт

Геометрия проверяется независимо от AutoCAD: полые трубы, скрытые линии, точное
разделение дуг передней пластиной, узкая щель видимости 0,01 мм, материал за срезом,
поперечные/продольные/смещённые разрезы, касание, обратные направления, перенос на
большие координаты, изменение диаметра, неизменность исходной модели, явный отказ
от неподдерживаемых деталей и взаимного проникновения.

Команды для разработчика:

    dotnet build src/AutoCAD/KotNode.AutoCAD.csproj -c Release -m:1 -p:BuildInParallel=false
    dotnet run --project tests/KotNode.Tests.csproj -c Release -- --projection-scene docs/prototype/scene.json
    python docs/prototype/render.py

Для сборки плагина на Linux дополнительно: -p:EnableWindowsTargeting=true.
Для запуска тестов на Linux дополнительно: -p:TargetFrameworks=net8.0.
Для сборки и упаковки на Windows: ./build.ps1.

На момент подготовки архива сборка DLL и автоматические проверки выполнены.
Запуск команд, отображение Hatch и цикл редактирования/обновления в AutoCAD
ещё требуют ручной проверки. Успешная сборка не подтверждает работу в хосте.

## Исправление штриховки (генератор 8)

Границы Hatch теперь извлекаются из полных Circle и явно замкнутых Polyline.
Для кольца задаются внешний и внутренний круг, для стенок — закрытые прямоугольники.
Временные объекты границ удаляются после вычисления неассоциативной штриховки.

После замены DLL перезапустить AutoCAD, открыть прежний тестовый DWG и выполнить
NAUPDATEVIEWS. Версия генератора повышена, поэтому виды пересчитаются даже без
изменения параметров деталей. Сохранить DWG, закрыть и открыть его повторно:
проверить полное кольцо с пустой полостью и всю площадь обеих стенок.

Добавлены проверки фабрики границ с API double: тип Circle, замкнутость Polyline,
площадь прямоугольной стенки и отклонение разорванных/неполных границ.
Эти проверки не выполняют нативный движок Hatch; итоговое отображение требует AutoCAD.
